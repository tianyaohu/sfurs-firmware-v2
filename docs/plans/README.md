# Technical development plans

One file per phased plan, named after the [PRD](../PRD.md) phase it serves,
e.g. `phase2-accurate-open-loop.md`. Paste or save the plan from plan mode
here before starting the work.

A plan lists ordered steps, each with a done-check (test or measurement). When
a step lands, tick it; when the whole plan is done, delete the file and leave
the outcome in the design log ([design/](../design/README.md)) and, if it
changed behaviour, in the affected doc.

Plans are intent, not state: if code and plan disagree, the code and
[ARCHITECTURE](../ARCHITECTURE.md) win.
